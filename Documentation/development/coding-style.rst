代码规范
========

C 代码遵循 Linux Kernel 代码规范（Documentation/process/coding-style.rst），下面只列出本项目的约定和与内核不同的地方。shell 脚本（start.sh）使用 8 个空格缩进，Makefile 使用 tab。

格式
----

- 缩进使用 tab，一个 tab 等于 8 列；一行不超过 80 列。``.clang-format`` 与 ``.editorconfig`` 已按此配置。
- 大括号：函数的左括号另起一行；其他语句的左括号与语句同行；``else`` 与右括号同行。
- 关键字后加空格（``if (``、``for (``），函数名后不加空格。指针星号靠右：``char *p``。
- 单行语句的 if/for 也要加花括号的场合以可读性为准；不要把两条语句写在同一行。
- 文件以 UTF-8 编码、LF 换行，文件末尾有换行。

命名与声明
----------

- 名字使用小写加下划线。对外公开的函数以 ``miku_`` 开头；模块内部的静态函数以模块名作前缀，例如 ``ui_``、``fzf_``。
- 声明放在块的开头（C89 风格）。编译选项 ``-Wdeclaration-after-statement`` 会检查。
- 不使用变长数组，不在头文件中定义变量。
- 常量放在 constants.h，不在源文件中散落魔数；确有必要的局部常量加注释说明来源。
- 结果不使用时递增优先写 ``++i``。

注释
----

- 每个源文件的开头有 SPDX 行、版权行和一段模块说明。
- 每个导出函数写函数注释：第一行为``函数名 - 作用``，随后用 ``@参数名:`` 说明每个参数，并说明返回值与线程约束。指针参数要写清楚是借用、转移还是由调用方释放。
- 复杂逻辑在关键步骤前写注释，说明为什么这样做，而不是重复代码在做什么。例如转换里的帧映射、音频 apad 的原因。
- 注释使用中文，关键标识符保持英文。

错误处理
--------

- 成功返回 0，失败返回负的 errno 值（如 ``-EINVAL``），与内核惯例一致。
- 资源按取得的相反顺序释放。需要多处退出时使用 goto 集中清理。

goto
----

goto 用于集中清理、跳出多层循环和失败路径。**每一个 goto 都必须有注释，说明它跳到哪里**，例如：

::

    if (!input || !result) {
            /* 跳到 out_free_paths，仅释放成功分配的路径。 */
            goto out_free_paths;
    }

警告与检查
----------

- 编译必须零警告通过（``-Wall -Wextra -Wpedantic -Wshadow -Wformat=2 -Wmissing-prototypes`` 等，并以 ``-Werror`` 视为错误）。
- 提交前运行 ``make test``；改动格式后运行 ``make format-check``。
- 不引入新的外部依赖。确需引入时同步更新 build.rst 中的依赖清单与 start.sh 的安装逻辑。
