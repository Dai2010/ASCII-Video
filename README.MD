# 新版本v5.4：新增「设置」与「已有视频」库、高光防漂白与「自动铺满」形态自适应

### 转换比例新增「自动铺满」、9:16 顺时针旋转与终端形态智能感知
- **比例首项升级为「自动铺满」**：将视频转换界面的比例首项由「原画」更名为「自动铺满」，
  消除认知困惑，默认即为最佳自适应方案。
- **手机 9:16 竖屏终端智能顺时针 90° 旋转与 100% 满铺**：当检测到当前终端为手机竖屏（如
  Termux 9:16，高远大于宽）且播放横屏视频时，自动顺时针旋转 90 度（`transpose=1`）并
  100% 满格铺满全部可见行和列（不多填也不少填），用户把手机横向手持即可直接获得全屏宽屏
  体验；桌面宽屏终端下则直接 1:1 全屏铺满；末行输出智能省略换行符以防止满屏滚屏抖动。
- **9:16 与 3:4 竖屏比例转换自动顺时针 90° 旋转**：在视频转换中选择 `9:16`（手机竖屏）或
  `3:4`（iPad 竖屏）比例（或竖屏终端下选择「自动铺满」）转换横屏片源时，解码管道自动应用
  `transpose=1` 顺时针旋转 90 度并自适应调整画布与网格宽高，彻底消除顶部和底部的巨大黑边，
  完美生成短视频与手机/平板竖屏规格。

### 主页面新增「设置」：方向键直选播放字号（4.0 ~ 12.5）
- **主菜单「设置」入口**：主页面新增 `设置` 选项（支持方向键、滚轮、鼠标点击与
  数字键 `1`~`5` 直达），进入后可直接使用方向键（`←`/`↓` 减小，`→`/`↑` 增大，
  步长 `0.5`）在 `4.0` 到 `12.5` 之间自由调节 Kitty 终端播放时的临时字体大小。
- **可视化调节与持久化**：界面提供微调框与可视化点槽进度条，字号改动自动持久化至
  `.miku-settings.tsv`，下次启动依然生效。
- **高密度字符画体验**：字号越小，终端行列密度成倍提高，字符画呈现出的细节越精细
  细腻；默认设为 `6.0`，用户可随心调小（如 `4.0` 极限超清）或按需调大。

### 主页面新增「已有视频」与自动规格后缀防覆盖
- **主菜单「已有视频」入口**：主页面新增 `已有视频` 选项，无需重新转换即可随时
  二次观看已生成的视频。
- **按「视频名 + 规格」智能去重与展示**：自动汇总历史转换记录（包括自定义输出
  名的视频）与当前目录下已有的成品文件；同一视频若规格相同则自动去重不重复排，
  若同一视频有多种不同规格则全部并列保留，每条右侧清晰显示
  `[宽x高 @ 帧率 · 风格 · 体积]`，回车或点击即可按该规格在终端全屏播放。
- **自动附带规格后缀**：自动输出命名（及同名异规格的自定义输出）会在扩展名前附带
  风格与分辨率帧率后缀（如 `-ascii-1920x1080@24.mp4`），防止同一视频转换不同规格
  时互相覆盖。

### 亮色与近白区域防漂白修复
- **分离白底分量与色度增益**：修复了原本 `miku_cell_color` 对所有亮色无差别乘上
  高增益导致 `>= 176` 的亮部全部封顶 `255`、浅粉/浅青/肤色/浅灰被推成刺眼惨白的
  问题。新增 `render_white_gain` 对三通道最小值（白底分量）在亮区做软膝衰减，在
  保持暗部鲜艳清晰的同时完整保留高光区域的色相与明暗层次；`CHAR_GAMMA` 同步调为
  `0.62`，避免高光字形糊成实心白块。

### Kitty 终端播放自适应缩字号与退出恢复
- **播放期间自动切换目标字号**：在 Kitty 终端（开启 `allow_remote_control yes`）
  播放视频时，计算字符网格前自动通过原生控制序列将当前窗口字号由默认（如 `12.5`）
  临时切换为设置中选定的字号（默认 `6.0`），让画面自动铺满更高密度的字符列。
- **全方位恢复默认字号**：绑定终端退出与信号清理路径，无论是正常播放结束、手动按
  `q` 退出，还是强制按 `Ctrl+C` 中断，均自动重置恢复为用户默认的终端字号。

# 新版本v5.3：大幅缩减输出体积与转换提速、安全加固及选择器改进

### 体积瘦身与编码调优（实测默认输出体积缩小约 77%）
- **`auto` 档位不再反向超分**：自动选档以源视频分辨率为上限（保底 `720p`），
  不再把 `720p` / `1080p` 源强行放大到 2K（`2560x1440`）；命令行同步补齐
  `src`（原画分辨率）档位支持，与终端界面保持一致。
- **字形与颜色双重跨帧稳定**：在跨帧保留相近墨量字形（`<= 3` 档）的基础上，同步
  记录每格上一帧 RGB 颜色；单通道色差在容忍阈值（`<= 12`）内时沿用上一帧颜色，
  消除暗部高增益放大的压缩底噪闪烁，让 H.264 帧间宏块顺利触发 `SKIP`。终端实时
  播放也已同步接入字形跨帧防抖。
- **x264 与音频编码参数瘦身**：默认 `CRF` 调为 `29`，将 `aq-mode=3` 改为标准
  `aq-mode=1:psy-rd=0,0:deblock=1,1`，避免向黑底字符边缘的振铃噪点倾斜码率；
  读取原视频抽取音轨时显式加上 `-vn -sn -dn` 在解复用层直接屏蔽画面/字幕/数据包，
  并将合并音轨的 AAC 码率由 `192k` 调整为 `128k`。实测原版 `miku.mp4` 10 秒片段在
  `auto` 下输出从 `32.8 MB` 降至 `6.7 MB`。

### 转换提速与渲染管线优化（实测整体提速约 2.5 倍）
- **静止与纯黑字符格跳过重绘**：画布在帧间持久复用，当某格本帧字形与颜色均未改
  变（或连续为空白黑格）时，直接跳过颜色提亮与 `paint_glyph` 逐像素混合；默认编
  译优化提升至 `-O3`，解码滤镜先缩放再按帧率采样。
- **编码器单次扫描与探测缓存**：`ffmpeg -encoders` 改为首次调用时单次扫描
  填满全部候选缓存（消除原先重复拉起 8~9 次子进程的 ~2 秒停顿），并对短片
  探测结果建立规格缓存，不再重复试探不存在的硬件设备。
- **管道缓冲与文本排版加速**：解码与编码管道启用 `1 MiB` 全缓冲（`setvbuf`）；
  界面尾部截断 `miku_ui_add_text_tail` 由 $O(N^2)$ 降为 $O(N)$，空白填充
  改为单次 `memset`。

### 内置文件选择器增强与安全加固
- **内置文件选择器优先**：常驻路径/过滤输入栏，支持大小写不敏感实时过滤、
  直接手输相对/绝对/`~/` 路径跳转，以及鼠标单次点击直达；手动按 `e` 编辑输入
  路径后自动同步派生输出名。
- **边界与命令安全加固**：`MIKU_PRESET` / `MIKU_CRF` 环境变量增加安全字符
  白名单校验；`ui_utf8_len` 补齐延续字节校验防止截断 UTF-8 越界读；`fzf`
  输出读取补齐缓冲上限检查；界面保留外部 `MIKU_NO_HW` 设置并在成功或取消后
  自动清理按 PID 命名的临时日志；`start.sh` 移除 Arch Linux `pacman -Sy`
  部分升级参数；新增 `make line` 八列缩进检查工具。

### 后续可继续提升与功能规划
- **渲染端直出 `YUV420P` / `NV12` 管道**：目前画布以 `RGB24`（`1080p` 每帧约
  `6.2 MB`）写入编码管道再由 FFmpeg 转 `yuv420p`；后续可在字符渲染阶段直接输出
  `YUV420P`（每帧降至 `3.1 MB`），将管道写入带宽再减半并省去全帧色彩转换开销。
- **多线程分块渲染与硬件编码精调**：针对高列数（`426` / `640` 列）及 `2K` 档位
  引入按行分块的 `pthread` 多线程并行渲染；并为 `NVENC` / `VAAPI` / `QSV` 补充
  针对字符画点阵调优的 `QP` 与 B 帧参数，缩小硬件编码与 `x264` 的体积差距。
- **可拓展的功能点位**：
  - **原视频 AAC 音轨直通（`-c:a copy`）**：源音轨已是标准 AAC 时支持免重编码
    直接流拷贝复用。
  - **自定义字符集与配色主题**：支持切换不同密度的 ASCII 字符集、复古单色终端
    配色（琥珀色、荧光绿、初音青 `#39C5BB`）及半块抖动（Dithering）模式。
  - **字幕保留与批量队列**：支持将源视频字幕烧录或封装进输出容器，并在终端界面
    提供多文件排队转换与“小体积分享 / 原画收藏”快捷预设。

# 新版本v5.0：终端界面 + 两种风格 + 比例/帧率可选
- **欢迎页**：葱绿大字 MIKU（半块字符拼的，纵向两倍分辨率）、下面一行随机歌词（传说曲单句，已逐条核对原文）、再下面是 `视频转换 / 视频播放 / 退出` 三个入口。方向键、`j`/`k`、`1`-`3` 数字键、滚轮、鼠标点击、手机触屏点击都能选（SGR 与 X10 两种鼠标编码都认，点击命中上下各放宽一行，手指点偏一点也能中）
- **两端都带文件选择器**：默认用**内置单列列表** —— 第 3 行是常驻输入栏，边打边过滤（大小写不敏感，中文名原样匹配），也可以直接输入路径回车进入；列表行**点一下就选定**，`←` 或 `Backspace` 回上一级，`Esc` 先清空输入栏再按一次退出。路径支持绝对路径、相对当前目录、`~/` 与 `..`。要外部工具就设 `MIKU_PICKER=fzf` 或 `MIKU_PICKER=dialog`（Termux 打包的 fzf 不支持鼠标，点行没反应，所以不再默认）；选完统一转成绝对路径；不想用列表就按 `e` 手打
- **自动命名的输出名按风格区分**：字符风格 `<输入名>-ascii.mp4`、色块风格 `<输入名>-block.mp4`，同一部片子转两种风格不会互相覆盖；自己在「输出」里改过名字之后，切换风格不再改动它
- **两种风格，转换与播放前都要先选**：
  - `字符`：原来的 ASCII 字形风格
  - `色块`：每格上下各一个像素、用 `▀` 的前景/背景上色，纵向细节是字符风格的两倍（跟终端里常见的色块播放器一个路子）
- **转换可以指定比例与帧率**：比例 `原画 / 16:9 / 9:16 / 1:1 / 4:3 / 21:9`，帧率 `原画 / 24 / 30 / 60`；**什么都不选就是原画比例 + 原画分辨率 + 原画帧率**
- **播放自动适配终端**：网格同时塞进终端宽高 —— 先按列铺满，再把行数压进 `行数-1`（留一行提示），反推的列数再夹回宽度，来回夹几次直到两边都满足；竖屏片吃满高度、横屏片吃满宽度。帧率默认原画（不超过 60）
- **播放时音画同步**：以 mpv 的 `time-pos` 为时钟原点（等它真正走动起来再对表），开头每 5 帧、之后每 15 帧校一次，偏差超过 0.5 秒直接对齐、否则按半量收敛；实测 3 秒片段全程偏差在 ±0.18 秒内。mpv 不可用时退回 ffplay，只做单调时钟节拍
- **两套配置互不影响**：播放页选过的文件不会带进转换页（反过来也一样），避免切过去一点「开始」就把刚看的内容又转一遍
- **文件体积**：字符风格满屏都是独立着色的字形，是这类画面里最难压的一种，实测约 `0.4 bit/像素` —— 720p30 约 11 Mbps、2K30 约 42 Mbps，大约是**同分辨率原片的 6 倍**。所以 20 MB 的片子转出几百 MB 属于正常，主要取决于选了多高的分辨率（2K 是 720p 的 4 倍像素）。默认 CRF 已从 19 调到 26（把字形放大 6 倍逐帧对比过，肉眼一致，体积减半），再往上 30+ 就会在字形边缘出噪点。另有**字形跨帧稳定**：某格的最佳字形与上一帧只差一两档墨量时继续用上一帧的字形，消掉亮度在档位边界抖动引起的逐帧翻字 —— 实测体积再降约两成，画面浓淡与颜色按 8 像素积分比对在 50 dB 以上（等同无损），动态画面还更不闪。想更小用 `MIKU_CRF=28`，要极限画质用 `MIKU_PRESET=medium`（慢约 2.5 倍）
- **点哪改哪**：配置页里点一项就立刻对它生效 —— 点「输入」直接开选择器、点「输出」直接进编辑、点开关与枚举立刻切到下一项、点「开始」就开跑，不用先选中再按回车
- 配置不再堆在首页：首页只有大字、歌词和三个入口，参数各自在对应的配置页里
- 命令行不加参数直接进界面；带参数仍走原来的 CLI，新加 `--block` 切到色块风格

# 新版本v4.5：三种模式 + 播放带声音 + start.sh 支持 Termux/macOS
- **三种模式**：默认只转码；`--play` 转完播放；`--play-only` 不转码、直接从源播放（最省 CPU，也不写文件）
- **临时文件自动清理**：`--play` 时省略输出文件名，就用 `$TMPDIR` 里的临时文件；播完、按 `q`、Ctrl+C 都会删掉，转换失败也不留半成品
- **播放带声音**：有音轨时用 `mpv --no-video`（没有 mpv 就用 `ffplay -nodisp`）同步放声，`--mute` 可关。音频解码只占个位数百分比 CPU，真正吃 CPU 的是往终端刷字符 —— 跟不上就 `--mute` 或把宽度调小
- **start.sh 重写成 POSIX sh**：不再依赖 `/bin/bash`（Termux 只有 `/bin/sh`）。检测顺序 Termux（`pkg install`，不整机升级、不用 sudo）→ macOS（brew）→ Debian/Fedora/RHEL/Arch（apt/dnf/yum/pacman），只装缺的包，`-march=native` 失败自动回落
- **跨系统内存探测**：Linux/Android 读 `/proc/meminfo`，macOS/BSD 走 `sysctl hw.memsize` / `hw.physmem`，读不到就不做内存限制
- 播放时终端放不下会自动减少列数；`--play` 可与 `--mute` 组合，`--play-only` 也可单独用

# 新版本v4.4：转完直接在终端播放 + 转换提速
- **终端播放**：加 `--play`，转码完成后用同一套字符选择与配色直接在终端里播一遍，按 `q` 退出。播放不经过视频编码，所以不额外花时间；终端放不下会自动减少列数，退出时恢复光标与颜色
- **x264 参数可用环境变量覆盖**：`MIKU_PRESET`、`MIKU_CRF`。想快就用 `MIKU_PRESET=ultrafast MIKU_CRF=21` —— 实测编码阶段耗时减半，同画质体积大约 +60%（ultrafast 关掉了 CABAC）
- **逐字符混色改成乘移位**：每像素三次 `/255` 换成精确的 `(x*a+128+((x*a+128)>>8))>>8`，`low` 档实测墙钟 −12%、CPU −11%，画质不变
- 实测口径（3 秒 720p24 源、2K 档、本机 8 核）：默认 veryfast 整链 6.9 秒；`ultrafast`+`crf21` 5.2 秒；把编码压到几乎免费只剩 4.6 秒 —— 也就是「渲染 + 管道」已经占了将近一半

# 新版本v4.3：按设备自动降级 + 硬件编码
- **输出规格不再写死**：`high` 2560x1440@60 / `mid` 1920x1080@30 / `low` 1280x720@24。默认 `auto`，按核数、内存和可用编码器自动选档 —— 低配设备会自动往下走，不再硬扛 2K60
- **手动指定质量**：第 4 个参数可以是 `auto` / `high` / `mid` / `low`，也可以直接给尺寸，如 `1920x1080` 或 `1920x1080@30`
- **优先硬件编码**：依次试 videotoolbox（macOS）/ nvenc / qsv / vaapi / mediacodec（Android），最后才轮到 libx264、mpeg4。每个候选都真编 8 帧再把帧数数回来，只认「能解出全部帧」的那个 —— 编不起来的、会吞帧的、写出坏包的都会被跳过
- **帧率按用户指定输出**：档位默认帧率仍不超过源帧率；显式选择 60 等帧率时按选择输出（源为 24fps 时用重复帧补到 60，画面不会更流畅，但规格与选择一致）
- **补全 BT.709 色彩标签**：旧版只写进了 `color_space`，`color_primaries` 与 `color_transfer` 是空的，播放器会自己猜 —— 猜错就是"饱和度偏低"那类色偏。现在 libx264 用 `-x264-params` 写全三件套，硬件编码器用一次流复制重封装补齐
- **失败自动兜底**：硬件编码中途失败或输出缺帧时，自动改用软件编码重做一次；失败的半成品文件会删掉
- 新增环境变量：`MIKU_NO_HW=1` 跳过所有硬件编码器（驱动有坑时的逃生口），`MIKU_CORES=N` 手工压核算力（省电、共享主机、老旧设备）
- 编译命令不变：仍然是 `gcc -O3 -std=c17 -Wall -Wextra -o miku miku.c -lm`

# 新版本v4.2：ASCII宽度默认跟随终端
- **宽度自动适配终端**：省略宽度参数（或写 `auto`）时，按当前终端列数决定每行字符数 —— 窗口多宽就铺多少列，不用再手算参数
- 终端列数超出 80-640 时夹到边界（太窄按 80 列、太宽按 640 列）；不在终端里运行（重定向、后台任务）时仍用默认 320 列
- 输出规格不变：仍强制 2560x1440 @ 60fps，字符大小依旧由 ASCII 宽度自动决定

# 新版本v4.1：饱和度修复 + 强制 2K 60fps
- **修复饱和度偏低**：旧版给颜色统一乘增益后逐通道截断到 255，亮色会被"冲白"（粉色变浅粉、天蓝变近白）。现在先适度提高饱和度，再按比例整体缩放，保持色相不变；同时给输出视频打上 BT.709 色彩标签，避免播放器解读色彩出现偏差。用同一帧画面实测，饱和度从原图的 0.34 掉到 0.14 修复为 0.31
- **输出强制 2560x1440（2K）@ 60fps**：与输入视频无关。输入不是 16:9 时，ASCII 画面居中显示、四周留黑边；输入不是 60fps 时通过重复帧补到 60fps（统一规格，不会让画面更流畅）
- **更高分辨率**：默认 320x90 个字符铺满 2K（原来默认 240 列）；ASCII 宽度范围改为 80-640
- 第 4 个参数（缩放系数）已取消，字符大小现在由 ASCII 宽度自动决定：字符宽 = 2560 / ASCII宽度（取偶数）
- 默认使用 x264 的 veryfast 预设保证速度，想要更小的文件可修改 `miku.c` 开头的 `X264_PRESET`、`X264_CRF`

# 使用方法

 - chmod +x start.sh
 - ./start.sh

  当你运行这个`Shell`脚本后, 它将会为您更新操作系统的所有包
然后自动拉取编译所需要的依赖包, 并自动编译`C`代码最后输出并运行启动.

你也可以直接用参数指定其他视频，不用再改脚本：

 - ./start.sh 输入.mp4 输出.mp4 [ASCII宽度]
 - 例如：./start.sh bad-1.mp4 bad-1-ascii.mp4 320

或者手动编译后单独运行转换程序：

 - gcc -O3 -march=native -std=c17 -Wall -Wextra -o miku miku.c -lm
 - ./miku bad-1.mp4 bad-1-ascii.mp4 320

参数说明：
 - ASCII宽度：每行字符数，80-640；省略该参数或写 `auto` 时按当前终端列数自动适配（不在终端里运行则用 320）
   - 320 -> 每个字符 8x16 像素（high 档下 320x90 个字符刚好铺满 2K）
   - 426 -> 每个字符 6x12 像素，426x120 个字符，字符更多更细（左右各留 2 像素黑边）
   - 数值越大画面越细腻，但单个字符越小、越不容易看清
 - 质量档位：`auto`（默认，自动选）/ `high` / `mid` / `low`，或直接给尺寸 `1920x1080[@30]`
   - 档位决定输出分辨率与默认帧率；默认帧率不超过源帧率，`WxH@FPS` 指定的帧率原样生效
   - 字符大小由「输出宽度 / ASCII宽度」自动决定，档位越低字符越小
 - 例：`./miku in.mp4 out.mp4 320 low`、`./miku in.mp4 out.mp4 auto 1920x1080@30`
 - 模式参数（位置随意，可以和别的参数混着写）：
   - 默认：只转码
   - `--play`：转完播放；**省略输出文件名**就用临时文件，播完/中断自动删除
   - `--play-only`：不转码，直接从源播放（最省 CPU，不写文件）
   - `--mute`：播放时不出声（默认有音轨就用 mpv 或 ffplay 放声音）
   - `--block`：色块风格（半块 ▀），不加就是字符风格
 - 不带任何参数运行 `./miku` 会打开终端界面（只在真终端里有效）
   - 例：`./miku --play in.mp4 160`、`./miku --play-only in.mp4 120 low`、`./miku --play --mute in.mp4 out.mp4`
